# Roadmap

This roadmap records sequencing, not delivery dates. Each phase requires review before moving into implementation.

## Phase 0 — Product foundation
- [x] Create the standalone ArCode Persona repository.
- [x] Record the product direction and confirmed customization domains.
- [x] Define independence from consuming platforms.
- [x] Record architecture boundaries and unresolved decisions.
- [ ] Confirm target devices and first-release scope.
- [ ] Approve the visual art direction.

## Phase 1 — Technical and visual validation
- [ ] Evaluate candidate 3D rendering approaches against approved target devices.
- [ ] Produce and review a small representative character prototype.
- [ ] Validate modular customization across face, skin, hair, eyes, clothing, and accessories.
- [ ] Measure load time, runtime responsiveness, and asset size.
- [ ] Select the asset format and production pipeline based on evidence.

## Phase 2 — Core persona experience
- [ ] Specify the canonical, versioned persona schema.
- [ ] Implement the customization experience and preview.
- [ ] Implement asset compatibility and validation.
- [ ] Define persistence, ownership, authorization, export, and deletion.
- [ ] Add automated tests and quality checks.

## Phase 3 — Integration readiness
- [ ] Specify and version the API/SDK contract.
- [ ] Add contract tests and integration examples.
- [ ] Define identity mapping and permission behavior.
- [ ] Complete security, privacy, and performance reviews.
- [ ] Obtain explicit approval before connecting any live platform.

## Phase 4 — First platform integration
- [ ] Select the first consuming ArCode platform.
- [ ] Implement integration in an isolated branch.
- [ ] Validate end-to-end behavior in a non-production environment.
- [ ] Review and approve the integration before release.

## Scope control

No platform integration, production deployment, or irreversible data change is authorized by this roadmap. Priorities and phase completion must be reviewed explicitly.
